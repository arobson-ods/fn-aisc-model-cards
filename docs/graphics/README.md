# Article graphics

Generated by `uv run python -m pipeline.graphics` from the report outputs. Edit the script, not the files. Each graphic comes as an SVG (sharp at any size; the alt text is inside the file too) and as a PNG at twice the size, for sites that don't accept SVG. They are drawn on their own light background, so they look the same on any page.

## 1. `eu_items` — Public model cards answer just over half of the EU form

**Alt text:** Bar chart. A typical public model card answers 26 of the 45 items on the EU Model Documentation Form. The share answered across all 14 cards, by section of the form: distribution and licences 99%; model properties 86%; intended use 71%; training process 71%; general information 64%; training data 40%; compute used in training 10%; energy use 2%. The form sends the training process, compute and energy items only to regulators.

## 2. `fact_sources` — Most of what model cards disclose is prose, not data

**Alt text:** Stacked bar showing where the 477 facts disclosed by 14 model cards come from. 17% come from the lab's own card metadata, 22% are generated by Hugging Face, 5% come from the repository's config.json, and 56% are written only in the README text. In total, 44% are machine-readable.

## 3. `schema_fields` — The standards have no field for some basic facts

**Alt text:** Table showing whether SPDX 3.0.1 and CycloneDX 1.7 each have a dedicated field for a fact.
- Both have a field: licence, base model, training datasets, limitations and training energy.
- Only SPDX has a field: context length.
- Only CycloneDX has a field: input types.
- Neither has one, so the fact can go only in free text: parameter count, knowledge cutoff date, training compute, training time, training hardware, languages, and how the model was derived.

## 4. `lineage` — The training-data trail goes cold at the base model

**Alt text:** Diagram of 11 model chains, each running from a published model back through the parent models its card declares. Each model is marked by whether its card metadata lists its training datasets.
- The OLMo chains list datasets at every step.
- Molmo2 and an InternVL model list their own datasets, but most of their parents list none.
- In the other 7 chains no model lists any training datasets: Llama, Gemma, Phi, SmolLM, Falcon, Granite, and a SmolLM fine-tune.
